GUIDE · OVERVIEW

系统设计与调用机制

Octos Audio API 是一套面向企业团队的全双工低延迟实时语音服务。服务由运行于云端的控制面 (Control Plane) 和部署在本地私有算力环境的桥接器 (Bridge) 协同提供。

为什么不是传统的文件上传接口？ 传统 ASR/TTS 接口要求客户端等待录音结束并将整个 WAV/MP3 文件 POST 上传，端到端延迟通常在 2~6 秒以上。 本项目采用「RTC 专网推流 + WebSocket 文本流」架构，说话过程实时切片并发推理，在用户停顿后 200ms 内即可完成最终断句。
GUIDE · AUTHENTICATION

鉴权认证规范

系统采用半公开服务机制（团队共用主凭证）。所有写入与会话级请求均需在 HTTP Header 中携带 Bearer Token：

HTTP Header 
Authorization: Bearer <CLIENT_ACCESS_TOKEN>

当浏览器创建会话成功后，控制面会自动签发限定路径的 HttpOnly Session Cookie，使后续的 WebSocket 连接无需在 URL 参数中暴露 Token。

GUIDE · QUICKSTART

快速开始示例

只需发起一个 POST 请求创建会话，即可获得 LiveKit 房间凭证及 WebSocket 订阅地址：

Terminal / Bash 
curl -X POST https://asr.example.com/api/v1/sessions \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'
Python 3 (httpx / requests) 
import httpx

BASE_URL = "https://asr.example.com"
TOKEN = "YOUR_ACCESS_TOKEN"

headers = {"Authorization": f"Bearer {TOKEN}"}
response = httpx.post(f"{BASE_URL}/api/v1/sessions", headers=headers, json={})
session = response.json()

print(f"Session ID: {session['sessionId']}")
print(f"LiveKit Room: {session['livekit']['room']}")
print(f"WS Path: {session['eventsWsPath']}")
Node.js / Browser (Fetch) 
const res = await fetch("https://asr.example.com/api/v1/sessions", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${YOUR_ACCESS_TOKEN}`,
    "Content-Type": "application/json"
  },
  body: "{}"
});
const session = await res.json();
console.log("Created session:", session.sessionId);

CLIENT INTEGRATION

LiveKit RTC 音频推流与订阅

客户端引入 LiveKit Web / Mobile SDK，加入 livekit.room 指定的房间并采集音频推流。Bridge 会作为远端受众接收 16kHz PCM 进行 VAD 和 ASR。

JavaScript (livekit-client SDK) 
const room = new LivekitClient.Room();

// 监听远端音频发布（用于实时收听 TTS 播报）
room.on(LivekitClient.RoomEvent.TrackSubscribed, (track) => {
  if (track.kind === 'audio') {
    const element = track.attach();
    element.play();
    document.body.appendChild(element);
  }
});

// 入会并发布麦克风（自动启用 AEC / NS / AGC）
await room.connect(livekit.url, livekit.token);
await room.localParticipant.setMicrophoneEnabled(true, {
  echoCancellation: true,
  noiseSuppression: true,
  autoGainControl: true
});
EVENT PROTOCOL

WebSocket 实时事件协议

连接 wss://asr.example.com/ws/client/{sessionId} 后，Bridge 将实时推送以下 JSON 事件：

asr.partial
流式中间打字机片段。在用户讲话未停顿时持续高频推送。
{ "type": "asr.partial", "sessionId": "...", "utteranceId": "...:1", "seq": 3, "text": "形式上说赛题应该" }
asr.final
最终断句结果。当 VAD 检测到静音或客户端主动 commit 时下发，附带各链路耗时 metrics。
{
  "type": "asr.final",
  "sessionId": "...",
  "utteranceId": "...:1",
  "seq": 4,
  "text": "形式上说，赛题应该不需要百分之百做正确。",
  "metrics": {
    "bridge": { "asrTotalMs": 286.4, "endpointMs": 420.0 }
  }
}
tts.started / tts.finished
TTS 朗读生命周期事件。tts.started 包含文字字符数，播放完后下发 tts.finished。
API REFERENCE

语音合成播报 · POST /api/v1/sessions/{id}/speak

在指定的活跃会话中触发 TTS 合成。音频直接推入 RTC 频道，用户无需轮询下载音频文件。

当前支持预设音色选择、语速调整和语气提示词，尚未接入音色创建、参考录音上传或声音克隆。

请求体字段规范 (JSON)

参数名 类型 必填 说明与限制
text string 是 待朗读文本，1~500 个字符。支持中文标点与英文。
voice string 否 预设音色标识。省略时使用 Bridge 配置的默认音色（默认 serena）。中文预设包括 serena, vivian, uncle_fu, dylan, eric；英文预设包括 ryan, aiden。可用音色取决于 Bridge 加载的 TTS 模型，填写新名字不会创建音色。
speed number 否 语速倍率。范围 0.2 ~ 3.0，默认 1.0。
instruct string 否 调整预设音色的语气或情感，最多 200 字。如 "温柔亲切地"、"非常严肃地"。此参数不会创建新音色。
cURL 示例 
curl -X POST https://asr.example.com/api/v1/sessions/YOUR_SESSION_ID/speak \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "你好，我是 Octos 实时语音助手。很高兴与你交流！",
    "voice": "serena",
    "speed": 1.0,
    "instruct": "温柔亲切地"
  }'
API REFERENCE

断句与会话释放

POST /api/v1/sessions/{id}/commit 立即截断并提交当前话语。适用于客户端用户点击“发送”或松开按键的手动打断场景。
DELETE /api/v1/sessions/{id} 释放会话。建议在页面卸载（pagehide/beforeunload）或通话挂断时调用。
